01 渲染架构概览

pi-agent-chat 采用三层渲染架构: 消息级外壳 → 内容级容器 → 块级分发器。每条 ChatMessage 携带 ContentBlock[] 数组, 由 ContentBlockRenderer 根据 block.type 路由到对应渲染组件。

MessageCard (消息级外壳: avatar + barColor + checkbox + 左侧边框) └─ MessageBubble (内容级容器, 遍历 ContentBlock[], 应用 block-border 颜色) └─ ContentBlockRenderer (块级分发器, 根据 block.type 选择渲染器) ├─ TextContentCard (block.type = text) ├─ ThinkingCard (block.type = thinking) ├─ ToolExecutionCard (通用 fallback, 工具名不在 registry 中) ├─ BashExecutionCard (toolName = bash, 含实时输出/LogViewer) ├─ ReadFileCard (toolName = read) ├─ WriteFileCard (toolName = write / edit / create_file) ├─ PreviewRenderer (→ ImageCard / UrlCard / HtmlCard / PdfCard / VideoCard / AudioCard / MarkdownCard / TextCard) ├─ LspExecutionCard (toolName = lsp / lsp_exec) ├─ TodoRenderer (toolName = todo) ├─ SubagentRenderer (toolName = subagent / subagent_resume) ├─ CoordinatorRenderer (7 delegate: _fork/_send/_status/_stop/_remove/_clear_stopped) ├─ UIInteractionCard (6 UI methods + 3 permission subtypes) ├─ MemoryCard (11 customTypes: prefetch/inject/extract/dream/created/failed/irrelevant) ├─ CompactionSummaryCard (block.type = compactionSummary) ├─ ErrorMessageCard (role = error) ├─ GoalCompleteCard (customType = supervisor_goal_complete) ├─ SupervisorContinueCard (customType = supervisor_continue) └─ CollapsedToolBlockGroup (>50 blocks 自动折叠)

02 共享原语 (Shared Primitives)

三种共享原语组件构成卡片渲染的基础设施, 被大多数卡片类型复用。

2.1 ToolCardHeader — 使用最广泛, 30+ 卡片共用的头部

Props

toolName status: running | done | error | background | terminated description collapsed? time? startedAt? endedAt? badge? action? onClick? mono? rtl? className?

Slot 布局

[icon 16x16] [description (flex-1, truncated)] [badge (shrink-0)] [time] [action] [running-indicator]

Status 颜色映射

Status 文本颜色 说明
running text-status-info 蓝色, 含 pulse 动画指示器
error / terminated text-status-error 红色
background text-status-warning 黄色
done base-color @ 70% 标准文本色降低透明度

CSS 基类

CHAT_CARD_HEADER_BASE_CLASS = "relative z-20 flex items-center gap-2 px-3 h-5 select-none border-l-[3px]"

2.2 SessionTaskCard — Subagent / Delegate 专用外壳

Props

blockId? toolName status title badge? action? time? startedAt? endedAt? meta?: string[] input? activity? result? error? details?

Section 组成

ToolCardHeader ├─ meta bar (tag 行) ├─ input section (指令/标题) ├─ activity summary (轮次/摘要) ├─ result section (Markdown) ├─ error section (错误详情) └─ details section (附加信息)

2.3 CardShell — UI Interaction 专用外壳

Props

block children

Features

rounded corners + status background tint + icon + title ├─ pending animation (等待响应) └─ responded / dismissed icon (已响应/已关闭)

07 源码实现问题清单 (Improvement Opportunities)

以下是在源码审计中发现的实际问题:

  1. 1. write/edit error fallback 不一致
    write / edit / create_file 的 error 状态 fallback 到 ToolExecutionCard, 但 read 无此条件。read 的错误使用专用渲染器, 其他工具名错误使用通用渲染器 → 同类卡片错误展示不一致。
  2. 2. subagent 不走 registry
    ContentBlockRenderer 中硬编码判断 subagent, 绕过 registry 机制。新增 agent 类工具时需手动修改分发器代码, 违反开闭原则。
  3. 3. MEMORY_HIDDEN_IN_CHAT 空集
    lsp-constants.ts 中定义为空集但 MessageCard 仍检查此集合 → 死代码, 建议清理。
  4. 4. 两种卡片外壳模式并存
    MessageCard (header + bar + checkbox + 左侧边框) vs MemoryCard / Compaction (紧凑行按钮) vs ToolExecutionCard (无外壳) vs UIInteractionCard (CardShell 圆角) → 四种外壳模式, 设计语言不统一。
  5. 5. 角色配色和块边框颜色两套独立系统
    MessageCard 用 ROLE_CONFIG.barColor, MessageBubble 用 getBlockBorderColor()。两套系统并行运行, 维护成本高。
  6. 6. Delegate 系列不统一
    DelegateCard 用 SessionTaskCard (完整外壳), 其他 6 种用 ToolCardHeader (轻量外壳) → 同一组件族内渲染结构不同, 用户体验不一致。
  7. 7. Bash 折叠后不可滚动
    手动折叠后不显示 "滚到底部" 按钮但仍接收输出 → 新输出不可见, 用户感知不到变化。
