基于 pi-agent-chat src/mainview 实际渲染代码 · 2026-07-07 · 覆盖 43 种卡片类型

概述

本文档从 pi-agent-chat/src/mainview/components/chat/ 源码中提取了所有消息卡片渲染器的类型定义、插槽结构、状态变体和交互行为。

渲染链路：MessageCard → MessageBubble → ContentBlockRenderer → 各渲染器。每条消息的 content 数组中的每个 block 根据 type 分发到对应渲染器。

核心问题：当前缺乏统一的 Card Shell / Slot 抽象，各渲染器各自实现标题栏、状态、折叠展开逻辑，导致视觉不一致。

渲染架构三层链路

总体架构分三层：

MessageCard (按 role 包裹) └─ MessageBubble (内容分发) ├─ TextContent → Markdown 渲染 ├─ toolExecution → ToolExecutionCard / BashRenderer / ReadFileCard / WriteFileCard / ... ├─ toolResult → ToolResult 渲染 ├─ thinking → ThinkingCard ├─ custom (memory_*) → MemoryCard ├─ custom (supervisor_continue) → SupervisorContinueCard ├─ special: delegate_reply → DelegateReplyCard ├─ special: hook_block → HookBlockCard ├─ special: lsp_block → LspBlockCard ├─ ui_interaction → CardShell + UIInteractionAnchor └─ preview → PreviewCard (含 8 子类型)

interface JwtPayload {
  sub: string;
  iss: string;
  exp: number;

export function verifyToken(token: string): JwtPayload {
  const secret = process.env.JWT_SECRET;
  if (!secret) throw new Error('JWT_SECRET not set');
  return jwt.verify(token, secret) as JwtPayload;
}

Slot 插槽规范

当前各卡片渲染器的核心插槽原语如下：

1. ToolCardHeader

[icon] [title (flex-1 min-w-0 truncate)] [badge (h-5)] [time] [chevron] Props: toolName, status, description, badge, time, action, onClick
用于：BashRenderer, ReadFileCard, WriteFileCard, SubagentRenderer, LspExecutionCard, ToolExecutionCard

2. SessionTaskCard

ToolCardHeader + [meta badges] + [input section] + [activity section] + [result section] + [error section] Props: blockId, toolName, status, title, badge, action, meta, input, activity, result, error
用于：SubagentExecutionCard（嵌套 SessionTaskCard 显示 activity rounds）

3. CardShell (UI Interaction)

rounded-lg px-3 py-2 + icon + title + pending animation status ∈ {pending, responded, dismissed, notified} method ∈ {askUserQuestion, confirm, select, input, editor, notify}
用于：UICardRenderer（AskUserQuestionCard, ConfirmCard, PathPermissionCard, SelectCard, InputCard, EditorCard）

4. Compact Row

icon + label (flex-1) + summary (truncate max-w-[200px]) + time + chevron min-h-6 text-[11px] rounded hover:bg-surface-hover/15
用于：MemoryCard, CompactionSummaryCard, GoalCompleteCard, SupervisorContinueCard

改进清单

从源码审计发现的 7 项关键问题：

1. write/edit/create_file error 时 fallback 到 ToolExecutionCard，但 read 无此条件
write/edit/create_file 在异常状态下回退到通用 ToolExecutionCard 渲染，而 ReadFileCard 没有对应的 fallback 逻辑，导致 read 出错时可能出现空白。
2. subagent 不走 registry，在 ContentBlockRenderer 中硬编码
SubagentExecutionCard 的 type 映射直接在 ContentBlockRenderer 的 switch-case 中硬编码，没有像工具卡片那样通过 toolUseRegistry 注册，不利于扩展。
3. MEMORY_HIDDEN_IN_CHAT 空集但仍有检查代码
常量 MEMORY_HIDDEN_IN_CHAT 定义为空集，但代码中仍有对它的引用和检查逻辑，属于死代码。
4. 三种卡片外壳模式并存
MessageCard（header+bar+checkbox+左侧边框）vs MemoryCard（compact row）vs ToolExecutionCard（无外壳）vs UIInteractionCard（CardShell 圆角）。四套外壳系统各自独立，缺乏统一抽象。
5. 角色配色和块边框颜色两套独立系统
role（user/assistant/tool）有自己的配色方案，而 block type（tool/thinking/memory）又有另一套边框颜色映射。两者互不感知，导致同一工具块在不同 role 下颜色不一致。
6. Delegate 系列不统一
DelegateCard 使用 SessionTaskCard 结构，而其他 6 种代理相关卡片使用 ToolCardHeader。delegate_assign/fork/reply/stop 之间也没有统一的状态机。
7. Bash 折叠后不可滚动
BashExecutionCard 在折叠状态下如果输出过长，body 区域没有设置 max-height 和 overflow，导致内容溢出容器。
